01 现状摸底

三个子代理已读完 change_tracker / management_snapshot / lib.rs / hooks_checker / dashboard.html，结论如下。

维度现状缺口
Tauri 桌面壳 单窗口；已有"关窗隐藏不退出"；CLI 子进程调度成熟（白名单安全边界） 无 tray-icon、无 notification、无 autostart、无后台定时器
变更检测 change_tracker 已有 compute_changes，存 data/state.yaml 维度极窄（只比 skills 工具增减）；management_snapshot 丰富快照不持久化、不对比；无定时/后台
Hook hooks_config_path 已声明 5 处；combined_checker 已读它做合规检测 管理台不透传、CLI 无编辑参数、GUI 无入口——管理/修复完全未消费
UI 范式 runCli → SNAP → renderXxx；data-action → confirmModal → runTaskModal 配置面板只覆盖 MCP 字段，无 hooks 编辑入口
核心架构原则（必须延续）：CLI 是唯一数据源（ADR: one engine, one data contract），Rust 壳只 spawn skill-mcp-studio 子进程，不在 Rust 里重写业务逻辑；所有写操作走 CLI 的 backup → atomic-write → validate → rollback 安全链。

03 四个功能

每个功能都建立在现有范式之上，不引入新的数据通路。

📍
功能 1

状态栏显示

macOS Menu Bar 常驻，关窗不退出，托盘提供唯一退出入口。

  • 启用 tray-icon feature + 模板图标（随深浅色自适应）
  • 菜单：显示管理台 / 立即巡检 / 开关后台 / 间隔选择 / 退出
  • 三态图标：空闲🟢 / 巡检中🔄 / 发现变更🔴
  • 点击弹框：单击 tray → 概览浮窗（客户端数/技能数/MCP/Hook/变更状态/上次巡检）
  • 浮窗底部：「打开管理台」「立即巡检」；失焦自动关闭
  • 保留现有"关窗隐藏" + Dock Reopen
🔄
功能 2

后台检测

长期后台定时巡检，只读不修复，让用户决定。

  • Rust 侧 tokio::time::interval 定时循环
  • 新增 --snapshot 轻量出口（不探活，~1.4s/次）
  • 设置面板可配：开关 + 间隔（5/15/30/60）+ 通知开关，持久化到 config.yaml 的 daemon 段
  • tray 菜单与设置面板双向同步，任一处改都即时生效
  • 每次 spawn CLI 子进程，结束即退，不常驻 Python
  • 只写 data/last_snapshot.yaml，绝不改客户端配置
🔔
功能 3

变更通知

检测到变更推送系统通知，点击查看详情，用户选修复或保持。

  • tauri-plugin-notification 推送系统通知
  • 点击通知 → 唤起窗口 + 跳变更详情面板
  • 四维度检测：IDE/Agent · MCP · Skill · Hook
  • 同变更只通知一次；"保持"后不再骚扰
  • 每条变更两个按钮：修复 / 保持
🪝
功能 4

Hook 管理

参照 MCP/skill 范式，把 Hook 从附属字段提升为独立管理域。

  • config.yaml 新增 hooks 段（events + clients + template）
  • 新增 hooks_inventory / hooks_fixer 模块
  • 新增 --list-hooks / --fix-hooks / --remove-hooks
  • management_snapshot 透传 hooks 字段
  • GUI 新增 Hook 面板（客户端×事件矩阵）

06 风险与边界

每条风险都有对应应对，不留裸奔项。

后台巡检开销
默认 15 分钟、不探活、~1.4s/次；tray 可暂停
通知骚扰
同变更只通知一次；聚合窗口；"保持"后不再通知
macOS 通知权限
首次发通知系统弹权限请求；tray 菜单加"开启通知"引导
后台误判
变更详情展示旧值→新值，用户可"保持"忽略
tray 跨平台
本期只做 macOS；Tauri 2 API 已统一，后续可平滑支持 Win/Linux
Hook 写入破坏配置
复用 MCP 的 backup→atomic-write→validate→rollback；--fix-hooks 支持 --dry-run
硬编码重复
ai_memory_checker 的 AI_MEMORY_HOOKS_PATHS 改为从 config.yaml 读取

确认后我按阶段开始实现。

  1. 巡检默认间隔（已纳入设置面板）
    默认 15 分钟合适？还是更短/更长？建议 15 分钟
  2. Hook 管理面板放哪
    独立一个 tab，还是并入 MCP 面板作为子区？建议独立 tab（维度不同）

    点击后直接执行修复，还是跳详情面板再确认？建议后者（符合现有 confirmModal 二次确认范式）
  5. 阶段顺序
    A→B→C→D→E 可以？还是先做托盘常驻（C）看效果？建议 A→B→C→D→E

    "长期后台"的配套，但会改系统登录项。建议加，但默认关闭，tray 菜单可开

## 三、整体 UI 协调性评审

### 3.1 已达成的一致性（值得肯定）

| 维度 | 证据 |
|---|---|
| **Token 纪律** | 间距/字号/圆角/颜色全部走 token（`--sp-*` / `--gap-*` / `--fs-*` / `--r-*` / `--ok/warn/err/accent`）。门禁强制：字面值 px、gap 族混用、幽灵圆角 token 全部拦截 |
| **圆角语言** | 统一三档：`--r-control`(8px 控件) / `--r-card`(12px 卡片) / `--r-hair`(3px 细条) / `--r-pill`(999px 胶囊) |
| **语义色** | 成功绿 / 警告橙 / 失败红 / 强调蓝，四色贯穿全站；不靠颜色单独传信息（状态词 + 图标） |
| **卡片语言** | 概览统计卡、设置卡、全量检查卡、升级确认卡：白底 + `--r-card` + 同一内边距梯度 |
| **表格语言** | 技能列表、配置备份、合并预览、升级确认表：统一 `th` 字号 `--fs-xs` muted、`td` `--fs-sm`、`--line` 分隔 |
| **按钮语言** | `btn-soft`(次要) / `cfm-btn-danger`(危险) / `cfm-btn-cancel`(取消) / `ghost.sm`(行内小操作)，同族同尺寸 |
| **弹框语言** | `cfm-card` 家族统一（标题 `--fs-md` 600 + 内容 + `actions` 区上边线分隔） |
| **状态覆盖** | 空态（说清为什么空）、加载态（spinner）、失败态（原因 + title 全文）均有实现 |

### 3.2 协调性缺陷（P2）

| # | 问题 | 位置 | 建议 |
|---|---|---|---|
| 1 | **跨页密度不一致**：Skills 页表格行高较松（`sp-4`），升级确认表行高较紧（`sp-1a`），同类数据表格密度不同 | Skills 页 / 升级模态 | 统一到 `sp-2`（8px），或明确「弹框内表格可更紧凑」的规则并写入 DESIGN.md |
| 2 | **版本列/更新列双日期无区隔**（同 2.1） | Skills 页 | 列名细分或加方向标识 |
| 3 | **组件数量偏多**：弹框家族有 `cfm-card` / `modal-form` / `ad-modal` / `task-card` / `upg-modal` 五套类名，样式有重叠 | 全局 | 长期建议归并为 2 套（确认类 / 表单类），减少维护面 |
| 4 | **升级模态 min-width 与项目主文不一致**：`min-width: min(440px, 92vw)` 是硬编码，未走 `--modal-w` 变量体系 | 升级模态 | 改用 `--modal-w` 变量，与其他弹框同源 |

### 3.3 可访问性

| 检查项 | 结论 |

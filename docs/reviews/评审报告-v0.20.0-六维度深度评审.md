## 一、执行摘要

**总体判断：工程质量偏上，但存在 1 个 critical 与一批跨维度共性的「单源真相漂移」问题，当前版本可发布但不宜作为长期演进的稳定基线。**

本次由 6 个专业评审智能体并行完成，覆盖产品、架构、开发、测试、UI/UX、构建六条线。共提炼 **54 条问题**：

| 严重度 | 数量 | 说明 |
|---|---|---|
| 🔴 critical | 1 | 桌面 App 产线部分功能不可用（三层契约漂移） |
| 🟠 high | 20 | 功能缺陷 / 重要技术债，需在下一版本优先处理 |
| 🟡 medium | 23 | 可维护性问题 / 一致性债 |
| 🟢 low | 10 | 风格 / 改进建议 |

**跨维度高频根因（去重后最该先治理的 4 类）：**

1. **版本元数据多源漂移** —— `pyproject.toml` 停在 `0.1.0`，README 徽章 / CHANGELOG 停在 `v0.19.0/build 103`，而 `version.json`/`Cargo.toml`/`tauri.conf.json` 已是 `0.20.0/build 104`。`bump_version.py` 不同步 pyproject / 徽章 / CHANGELOG。这条在「产品」「开发」「架构」「构建」四个维度被**独立命中 4 次**，是最突出的共性问题。
2. **CLI 契约三重漂移** —— Rust `lib.rs` 白名单 ↔ `gui/dashboard.html` 调用 ↔ `scan.py` argparse 各自为政，导致桌面 App 内「备份/导出/重命名/删除技能」不可用（critical），以及 `--hermes/--ai-memory/--fix-ai-memory` 成为失效门面 / 死代码。
3. **CI 完全没有测试门禁** —— 三个 build workflow 均无 test job，381 个测试从不被 CI 强制执行；且 8 个 core 模块（含删除文件 / git pull / 网络 / 写备份等高危路径）零测试覆盖。
4. **安全相关缺口** —— `auth_token` 明文以 0o644 落盘；`open_url` Windows `cmd /C start` 命令注入面（CSP=null + withGlobalTauri 放大）；`certifi` 未声明依赖导致 macOS python.org 构建 TLS 校验退化。

**做得好的地方（详见各维度 strengths）：**
- 写路径安全链（备份→原子写→re-parse 校验→回滚）被提升为贯穿产品承诺，且 `mcp_fixer`/`config_store`/`endpoint_store` 单点复用；
- `transport.py` 跨平台子进程抽象质量高（永不 shell=True、单一 deadline、Windows CREATE_NO_WINDOW、后台线程+队列）；
- 退出码 0/1/2 三层语义分层清晰并有专门测试锁定；
- 测试资产健康：34 文件 381 用例在 Python 3.11 下一次性全绿；
- `.gitignore` 完整（`git ls-files` 证实零构建产物入库），Rust 侧 `#[cfg]` 三平台分派正确；
- ADR/决策记录体系严谨，代码大量回写 ADR 编号，演进有据可查。

### 2.2 架构（1 critical / 3 high / 4 medium / 2 low）

#### 🔴 Critical

**A-1. 三层契约漂移：Rust allowlist ↔ GUI ↔ argparse 各自为政，桌面 App 部分功能不可用**
调用链 `dashboard.html → Tauri invoke(run_cli) → spawn skill-mcp-studio`。(1) `scan.py` 定义了 `--backup-skill/--export-skill/--rename-skill/--delete-skill` 且 dashboard 也调用它们（`dashboard.html:2524/2532/2566/2583`），但这 4 个 flag 均不在 `lib.rs` ALLOWED 里，运行即被「子命令不在白名单内」拒绝——**「备份/导出/重命名/删除技能」在桌面 App 内全部不可用**。(2) 反向：`lib.rs` ALLOWED 含 `--update-client`（`lib.rs:176`）与 dashboard「编辑客户端」传的 `--update-client`（`dashboard.html:3024`），但 `scan.py` 根本没有该 flag，argparse 报 unrecognized arguments 并以 exit 2 失败。
- 证据：`src-tauri/src/lib.rs:161-187`、`gui/dashboard.html:2524/3024`、`scan.py:1205-1228`
- 建议：把 CLI 子命令/flag 清单收敛为单一生成源（一个 Python 模块导出 schema，argparse 与 Rust allowlist 都从它派生），并补一致性回归测试。

#### 🔴 High

**A-2. result_ok 把「未探测」与「探测失败」混为一谈，config-only 运行永远无法 exit 0**
`check_agents` 在 `live_probe=False` 时填 `mcp_initialize_ok=False`，而 `result_ok`（`combined_checker.py:289-290`）硬性要求二者为 True，导致默认 `python3 scan.py` / `--mcp`（不带 `--probe-mcp`）在 installed 客户端下恒返回退出码 1，破坏「0=全绿」契约。
- 证据：`core/combined_checker.py:173-176/225-226/280-298`、`scan.py:1442-1444/1827-1830`
- 建议：引入探测三态（probed-ok / probed-failed / not-probed），not-probed 不计为失败。

**A-3. 客户端注册表单源真相拆成 mcp_tools 与 tools 两段，去重合并丢字段**
`config.yaml` mcp_tools 段只有 MCP 字段、tools 段只有 skills 字段，`tool_registry.effective_tools` 去重后保留 mcp_tools 条目、丢失 skills_paths，迫使 management_snapshot / combined_checker 多处反查 scan rows 补洞。
- 证据：`config.yaml:72-165/173-223`、`core/tool_registry.py:152-182`、`core/management_snapshot.py:224-227`
- 建议：合并为客户端单一 schema，effective_tools 做字段级 union。

**A-4. 客户端注册表在 ≥5 处重复定义且相互矛盾**
Reasonix 在 `legacy_checker` 是 `~/.reasonix/config.json` + reasonix-json，在 `mainstream_registry`/`config.yaml` 是 `~/.reasonix/config.toml` + reasonix_toml；Cherry Studio、Qoder 同样冲突。同一客户端不同链路得到不同结论。
- 证据：`core/legacy_checker.py:33-57` vs `core/mainstream_registry.py:717-730`、`config.yaml:119-128`
- 建议：收敛为唯一注册表，一致性测试锁死 config_path/format/key_path。

#### 🟡 Medium
- **A-5** 真实 import 环，靠 6+ 处惰性 import 打补丁（`skill_state.py:298`、`transport.py:100`、`tool_registry.py:161-163`、`config_store.py:305/546`、`profile_loader.py:121/139`、`mcp_fixer.py:688`）
- **A-6** key 解析/序列化重复：TOML/Reasonix/cordis YAML 各两份（`mcp_checker.py` vs `legacy_checker.py` vs `mcp_fixer.py`）
- **A-7** `scan.py main()` 是 ~900 行 god-function，阶段编号自相矛盾（阶段 5 打印 Phase 4、阶段 6 打印 Phase 5）
- **A-8** profile 被重载为 endpoint，且 `unified_mcp` 旧键残留形成静默 no-op 分支（`mcp_fixer.py:812`、`combined_checker.py:159`、`management_snapshot.py:375`）

#### 🟢 Low
- **A-9** 版本单源真相未覆盖 pyproject.toml（`pyproject.toml:7` 仍 0.1.0）
- **A-10** 命名残留：MCP clientInfo 两处身份不一致（`mcp_probe.py:153` "skills-mcp-unifier" vs `transport.py:310` "skill-mcp-studio"），scan.py/reporter.py 仍用旧名 Skills Unifier

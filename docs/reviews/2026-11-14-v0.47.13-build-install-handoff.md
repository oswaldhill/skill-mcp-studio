## 7. 记忆写入受阻（需人工处置）

| 尝试 | 结果 |
|---|---|
| `note_write`（repository_key = skill-mcp-studio） | `repository identity fingerprint mismatch` |
| `note_write`（repository_key = 绑定项目的 PuddingHomeLan） | `direct writer client differs from authenticated principal` |
| `event_read` 精确回读 | `not_found` —— 确认**两次写入均未落库**，无半成品 |

根因是**项目错配 + 设备未授权**：

- 本会话在服务端被绑定到 **PuddingHomeLan**（`01a0b798`），而实际工作仓库是
  skill-mcp-studio，于是用哪个身份的 `repository_key` 都不对 —— 前者报
  `repository identity fingerprint mismatch`，后者报
  `direct writer client differs from authenticated principal`。
- skill-mcp-studio 项目**已注册**，但**未授权给本设备**。

> 🔄 **2026-11-14 晚更正（此前记录有误）**：本文早先写「skill-mcp-studio 未注册、
> 且注册受 resolution_token 死锁所阻」，这是**错的**。实测现在
> `project_resolve_identity` 返回的是：
>
> ```
> project is not allowed for this client
> ```
>
> 而不是早先的 `project is not registered in the server manifest`。
> **错误码已从「未注册」变为「未授权」**，说明项目已经注册好了，
> 只差把本项目加进本设备的 `allowed_project_ids`。
>
> 这也解释了为什么注册接口报 `resolution token invalid or expired` ——
> 项目既已存在，自然不需要（也拿不到）新注册用的 token。
> 当时把「拿不到 token」误判成死锁，是错误归因。

另注：本次会话期间 `allowed_project_ids` 从 11 个收窄到 2 个，授权范围发生过变化。

按规则（不伪造身份字段、不盲试、不降级为其他通道），未做进一步重试。

**为什么客户端无法自行解决**：`hermes_device_status` 返回 `management_allowed: false`，
`hermes_device_preflight(action=manage)` 返回 `device management not authorized`。
项目/设备授权是管理端能力，客户端只能报告，不能授予。

**处置步骤（需管理端在 NAS 上执行）**：

1. 把 `v1|codeup.aliyun.com/oswaldhill/skill-mcp-studio|.` 对应项目加入设备
   `6e563738-c08e-413b-b809-1dcc43dde223`（Mac mini）的项目授权列表；
2. 授权后，本会话/新会话用 `project_resolve_identity` 复核应变为 `matched`；
3. 再 `session_binding_put` 绑定到该项目下的任务（当前绑定仍指向 PuddingHomeLan）。

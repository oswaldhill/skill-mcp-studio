# 阶段五管理台评审整改报告

> 评审日期：2026-09-05
> 评审范围：skill-mcp-studio 阶段五「三栏管理台」桌面 App（IDE/Agent · Skills · MCP）
> 评审方法：四角度并行智能体评审（架构 / UI-UX / 数据契约 / 功能覆盖）+ 截图实况核验
> 评审产物：`docs/review-arch.json` / `review-uiux.json` / `review-data.json` / `review-feat.json`

---

## 一、总体评价

三栏骨架与读侧数据流（`endpoint_library` 声明式期望 / `mcp_inventory` 观测式清单 / `management_snapshot` 只读编排器）抽象清晰，producer/consumer 边界合理；安全链（备份 → 原子写 → re-parse → 回滚）到位。但存在**三处阻断项**直接造成截图硬伤与需求未落地：

| # | 阻断项 | 影响 |
|---|--------|------|
| B1 | `skills_compliant` 语义 BUG（数据层与 `installed` 解耦 + UI 无守卫） | 截图「未安装却 ✓合规 root」硬伤 |
| B2 | 「一键合并」按钮仅 `--dry-run` 未实写 | 需求 2(d) 未落地，按钮名不副实 |
| B3 | `unified_dir` 个人拓扑被写进版本控制 `config.yaml` | 违背自身「主干零个人拓扑」隔离原则 |

四角度共发现 **31 条**问题（blocker 3 / high 9 / medium 13 / low 6）。当前功能覆盖度约 **50%**，核心写操作与判定矩阵需补齐。

## 二、阻断项与高优先级问题清单

### 🔴 Blocker（阻断验收，必须先修）

| ID | 标题 | 根因定位 | 整改方案 |
|----|------|----------|----------|
| **B1** / DATA-1 / UI-1 | 未安装客户端误报「Skills 路径 ✓合规」 | `_client_skill_stats`（management_snapshot.py:46）`compliant = bool(rows) and all(s=='correct')` 与 `installed` 解耦；未安装客户端因残留 root 软链 → rows 非空全 correct → compliant=True；`renderAgents`（dashboard.html:212）三元无 `a.installed` 守卫 | ① 数据层：`_agent_entry` 用 `install['installed'] and skill_stats['skills_compliant']` 收敛；② UI：`renderAgents` 改为 `${!a.installed?'<span class=ok-na>— 未安装</span>':(a.skills_compliant?'✓合规':'✗不合规')}` + 未安装卡片灰显；③ `combined_checker._skills_compliant` 同步按 installed 收敛 |
| **B2** / FEAT-2 | 「一键合并」按钮仅 dry-run 不实写 | `btn-merge-all`（dashboard.html:406）硬编码 `runCli(['--fix-skills','--dry-run'])` | 拆两步：先 `--fix-skills --dry-run` 预览变更清单 → 用户确认后再不带 `--dry-run` 实写（复用 `mcp_fixer` 安全链）→ 写后 `loadInternal` 复检刷新 |
| **B3** / ARCH-1 | `set_unified_dir` 写版本控制 `config.yaml`，三处写目标分裂 | `config_store.set_unified_dir`（config_store.py:63-68）正则改写 `config.yaml`；而 `endpoint_store` 落 profile_sources（gitignored）、`add_discovered_client` 落 `data/`（gitignored） | `set_unified_dir` 改写 gitignored 覆盖文件（如 `data/local_overrides.yaml`），由 `apply_profile_sources` 合并 `unified_skills_dir`；主干 `config.yaml` 只保留默认值 |

### 🟠 High（严重，影响可用性/需求完整性）

| ID | 标题 | 整改方案 |
|----|------|----------|
| **ARCH-2** | `run_cli` 透传任意 argv 无白名单，裸 stdout/stderr 回传前端 | Tauri 边界加子命令白名单（只读 + 已登记写命令），`--config`/`--profile` 重定向参数拒绝或固定主干；返回 stdout/stderr 做路径裁剪与敏感键过滤 |
| **ARCH-3** | `_agent_entry` 合并 `mcp_tools`+`tools` 异构注册表丢类型信息，tools 条目被误报「挂全量端点」 | `_agent_entry` 加 `source: "mcp_tools"\|"tools"` 标记；tools 条目不下发 `mcp_attach`（置 null）、`fix_supported=False`；UI 据 source 决定是否渲染端点列与修复按钮 |
| **ARCH-4** | `apply_profile_sources` 在 `load_config` 期原地改写共享 config 的 `mcp_attach`，无前置校验，所有只读路径被污染 | overlay 应用改为返回新副本而非原地改写；或 overlay 引用的端点键先 `validate_attachment` 校验；删除未启用的 `get_client_attach_overlay` 或改为唯一读源消除双实现 |
| **UI-2** | `install_evidence` 渲染在 nowrap 容器被裁切不可见 | evidence 改 pill-list 换行布局 + tooltip 完整路径 |
| **UI-3** | 「挂载端点」列表被 nowrap+ellipsis 截断成「generic-http, h…」 | 改用 `.pill-list`+.skill-pill 多标签换行布局替换单 `.v` span |
| **UI-4** | `type` 字段大面积显示「—」 | `_agent_entry` 调 `scanner.infer_tool_type(name)` 兜底 type；或注册表补全 type 字段 |
| **UI-5** | 客户端卡片无点击/编辑/详情入口，无法修改配置 | 卡片加「编辑」按钮展开右侧抽屉，含 config_path/mcp_attach/skills_paths 修改表单（需 CLI 补 `--update-client`） |
| **UI-6** | `doRescan` 用 undefined 覆盖数据 + 异步期间无加载态 | `doRescan` 改为直接调 `loadInternal()`；加载前置 spinner + 禁用按钮 |
| **FEAT-1** | `--add-client` 只能录 skills-only 客户端，不能加带 MCP 的 | argparse 增 `--client-config-path/--client-mcp-format/--client-mcp-key-path`；`add_discovered_client` 透传；GUI 弹窗补对应输入项 |
| **FEAT-4** | 自动发现结果 GUI 不触发不展示 | 「重新扫描」改传 `--discover`；management 快照输出 `discovered_candidates`，IDE/Agent 栏以「待确认」卡片展示 + 接受/忽略操作 |
| **FEAT-5** | Skills 技能清单仅 pill，缺「技能×客户端」矩阵 | Skills 栏渲染技能×客户端矩阵（复用 `--list-skill-states` 数据），单元格 on=绿/off=黄/-=灰，支持点击启停 |

## 四、整改路线图（分批落地）

### 批次一：阻断项修复（B1/B2/B3）— 必须先做
1. **B1 数据层 + UI 守卫**：`management_snapshot._agent_entry` + `combined_checker._skills_compliant` 按 installed 收敛；`dashboard.html renderAgents` 三元加守卫 + 未安装卡片灰显
2. **B2 一键合并实写**：`btn-merge-all` 改两步（预览 → 确认实写）
3. **B3 unified_dir 写目标统一**：`config_store.set_unified_dir` 改写 `data/local_overrides.yaml`，`apply_profile_sources` 合并该键
- 验收：截图复测无「未安装✓合规」；合并按钮能真写；`git status` 显示 config.yaml 不被改

### 批次二：高优可用性（UI-2/3/4/5/6 + ARCH-3）— 让信息看得全、可编辑
4. **UI-2/3 截断修复**：挂载端点 + install_evidence 改 pill-list 换行 + tooltip
5. **UI-4 type 兜底**：`_agent_entry` 调 `infer_tool_type`
6. **UI-5 卡片编辑入口**：加「编辑」按钮 + 抽屉表单（需 CLI 补 `--update-client`）
7. **UI-6 加载态 + doRescan 修复**
8. **ARCH-3 注册表来源标记**：`_agent_entry` 加 `source` 字段，tools 条目不下发 mcp_attach

### 批次三：功能补全（FEAT-1/4/5 + FEAT-3/6/8）— 让需求完整
9. **FEAT-1 带 MCP 的客户端添加**：CLI + 弹窗补 MCP 配置字段
10. **FEAT-4 自动发现可见**：「重新扫描」传 `--discover`，展示 discovered_candidates
11. **FEAT-5 技能×客户端矩阵**：Skills 栏渲染矩阵
12. **FEAT-3 客户端×端点判定矩阵**：MCP 栏渲染矩阵
13. **FEAT-6 端点编辑 + stdio 支持**：端点表加「编辑」，添加弹窗补 transport 选择
14. **FEAT-8 查看 MCP 配置原文**：卡片加「查看配置」按钮

### 批次四：架构加固 + 收尾（ARCH-2/4 + 死代码 + 低优）
15. **ARCH-2 run_cli 白名单**：Tauri 边界加子命令白名单 + 返回脱敏
16. **ARCH-4 overlay 副作用收敛**：返回副本而非原地改写 + 前置校验
17. **ARCH-5 死代码清理**：删 `_endpoint_entry`、`_all_endpoints` 内联、`get_client_attach_overlay`
18. 中低优 UI/数据项收口

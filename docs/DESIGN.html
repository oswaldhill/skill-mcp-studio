界面规范（Skill MCP Studio 管理台）

本文件是 gui/dashboard.html 的唯一设计依据。所有页面与弹窗都必须遵守； 新增界面时先在这里找现成组件，找不到再补，并把补的那条写回来。

7 章节 18 检查项 28 项测试兜底 来源 docs/DESIGN.md

0设计判断（Design Read）#

定位

桌面端开发者工具管理台（dense product UI / admin panel）， 面向同时使用多个 AI Agent、需要统一管技能与 MCP 的开发者。

三档标尺（本项目取值，非通用默认）：

标尺取值理由
DESIGN_VARIANCE3 管理台要可预测。左右对齐、栅格稳定，不做非对称艺术排版。
MOTION_INTENSITY3 工具界面。只保留 hover / active / 展开收起的状态反馈，不做入场编排。
VISUAL_DENSITY6 数据密集但仍需呼吸感。信息分区块、留白分层，不排成电子表。

与 taste-skill 的关系：taste-skill 第 13 节把 dashboard / admin panel 列为 out of scope，并将此类界面指向 Fluent / Carbon / Polaris 等设计系统。本项目 不引入外部框架，沿用自身 token 体系；只采用 taste-skill 中与界面类型无关的 质量规则：颜色一致性锁、形状一致性锁、按钮与表单对比度、完整状态覆盖、 卡片克制、内容密度、禁用 em-dash。

1Token 体系（唯一取值来源）#

所有颜色、字号、圆角、阴影、缓动必须取自 :root，不得写字面值。

类别Token用途

圆角四档都要用：--r-hair 专给 10-11px 的小徽标（如变更面板的维度标签）， 它比 --r-control 更贴合小尺寸；不要用字面值 4px 凑合。

颜色锁

强调色只有 --accent 一个。任何新界面不得引入第二强调色。

形状锁

圆角只用上表四档。控件 8px，卡片 12px，胶囊用 pill，小徽标用 hair。

主题锁

浅色与深色两套 token 同步维护，不得只改一侧。

字体锁

正文用 --sans；数字、路径、包名、代码用 --mono。

2组件规约#

2.1 按钮#

基础按钮（全局 button 元素样式已提供：面板底、描边、圆角 --r-control、悬停变色、按压回落）：

类用途规则
button.primary一屏一个主操作--accent 底 + --on-accent 字
button.btn-soft次级操作（最常用）面板底 + --line-strong 描边
button.ghost三级/文字按钮无底无边，悬停才显形
button.danger / .btn-soft.danger破坏性操作--err 字与边，悬停实心红 + --on-accent 字
button.sm紧凑场合（表格行内）与基础按钮叠加使用，如 btn-soft sm

场景化变体（只在特定容器内使用，不跨场景复用）：

类限定场景
btn-save / btn-cancel表单弹窗底部的主/次操作
cfm-btn-danger / cfm-btn-cancel确认框的两个出口
ad-clean-btn / ad-clean整理建议卡的清理动作
adv-all-btn / adv-merge-btn整理建议的批量合并动作

不是按钮的控件（不要按按钮规范要求它们）： seg-btn、view-btn、settings-tab、nav-item、pm-item、pal-item。 这些是分段控件 / 视图切换 / 导航项 / 菜单项，各有自己的选中态表达。

硬规则

一屏只允许一个 primary。

硬规则

破坏性操作必须用 danger 变体，不得用 primary 伪装。

硬规则

按钮文字不得换行（white-space: nowrap 已全局声明）；对比度满足 WCAG AA （正文 4.5:1，18px 以上 3:1）。

硬规则

新增按钮变体时必须回来登记到本表。

2.2 列表行（.list-row）#

用于「多条同类条目 + 每行一个操作」的场景。这是市场、更新检查、技能列表的统一形态。

┌──────────────────────────────────────────────┐
│ 主标题（--text, --fs-base, mono 用于包名）      [操作] │
│ 元信息（--faint, --fs-xs）                            │
└──────────────────────────────────────────────┘
  • 行与行之间用 --line 分隔，不用每行一个卡片（卡片会撑高列表）。
  • 主标题可截断（text-overflow: ellipsis），完整值放 title 属性。
  • 操作按钮右对齐，纵向居中；同一列表内按钮文案一致。

2.3 卡片（.card）#

只在需要表达「独立实体」时使用（技能卡、MCP 服务卡）。 不要用卡片堆一长串同类条目，那是列表行的职责。

2.4 元信息与数字#

  • 数字、包名、路径、版本号一律 --mono + --faint 或 --muted。
  • 数量单位用中文（「3.6 万次安装」），不直接透出上游英文原文。
  • 不得展示假精确数字；来自上游的原始值如实标注。

2.5 状态覆盖（每个数据区都必须有）#

状态要求
加载中有明确文案说明在做什么、大概多久
空说明「为什么空」以及「怎么让它不空」，不留白屏
错误就地显示原因，不弹窗、不吞掉

2.6 工具条（.toolbar）#

搜索框 + 操作按钮同排。搜索框占满剩余宽度，按钮固定宽度，间距 8px。 输入框必须有 placeholder 与 aria-label。

2.7 变更卡片（.chg-card）#

用于「变更详情」面板：每条变更一行决策（修复 / 保持）。

┌────────────────────────────────────────────────┐
│▌[维度] 名称                          [修复][保持]│
│  详情（旧值 -> 新值）                            │
└────────────────────────────────────────────────┘
  • 左侧 3px 状态条表达变更类型：added 绿 / removed 红 / 其余橙。 颜色是辅助信息，名称与详情文字必须独立可读（色盲可用）。
  • 维度标签用 --r-hair 圆角 + --faint 字，不要做成彩色胶囊 （那会与 --accent 抢注意力）。
  • 动作按钮最小高度 32px（触达目标），主操作「修复」用 .chg-btn.primary。
  • 卡片悬停只改边框与阴影，不用 scale，避免列表位移。
  • 统计行用 .chg-pill：显示当前数量；有变更时才追加 +N 徽标并转为 hot（--warn-bg）。没有变更时也必须显示数量，不能是一排 0。

2.8 托盘弹框（gui/popover.html）#

独立的 macOS 风格浮层，不复用管理台的 token（它是叠在系统菜单栏上的 另一套视觉：毛玻璃、无边框圆角窗）。

  • 面板：rgba(248,248,250,.88) + backdrop-filter: blur(30px)， 圆角 14px，窗口开启 transparent 让圆角外真正透明。
  • 状态点三态：绿（已同步）/ 橙（有变更）/ 灰 + 呼吸动画（显示的是缓存， 正在刷新）。缓存态必须给出提示，不能让用户把旧数据当成实时结果。
  • 窗口高度由内容决定（fitWindow 量完面板高度再 setSize）， 最小 200px；首屏先用 localStorage 缓存渲染，再后台刷新。
  • 定位由 Rust 侧负责：水平居中对齐托盘图标、垂直贴菜单栏下方； 没有图标坐标时（菜单触发）退回右上角。

3排版与间距#

  • 区块间距用 16 / 20 / 24px 三档，同一页面保持同一节奏。
  • 面板内边距 20px；卡片内边距 16px；列表行内边距 12px 16px。
  • 一行元信息里的分隔符最多一个，优先用换行或留白，不用符号堆砌。
  • 中文正文不手动加空格；中英文混排不加空格，靠字体回退处理。
  • 禁用 em-dash：正文、标题、标签、按钮文案一律用普通连字符或改写句子。

3b可访问性（硬要求，非可选）#

这几条由测试或明确的交互约束兜底，新界面必须满足。

要求做法为什么
键盘可达 交互元素保留 :focus-visible 外环（2px solid --accent，偏移 2px） 无鼠标用户需要知道焦点在哪
抑制 outline 必须给替代 若写了 outline: none，同一条规则里必须补 box-shadow 焦点态 否则键盘用户完全看不到焦点
尊重减少动效 所有 animation / transition 在 @media (prefers-reduced-motion: reduce) 里关闭 前庭敏感用户会因动效不适
触达目标 可点元素最小 32px 高（弹框内）/ 44px（移动端） 误触率
不靠颜色单独表意 状态同时有文字或形状（如变更卡的状态条 + 文字详情） 色盲可用
图标用 SVG 不用 emoji 当 UI 图标；统一 viewBox="0 0 24 24" 跨平台渲染一致
可点元素有指针 cursor: pointer 可发现性
已知例外

.status-dot 的呼吸动画是「正在刷新」的唯一视觉提示， 在 reduced-motion 下关闭动画，但 title 文案仍在，语义不丢失。

4落地页配方（不适用于本项目）#

以下 taste-skill 条目本项目不采用，仅记录以便区分：

  • Hero / 首屏构图、bento 网格、marquee、滚动编排、大字号展示标题；
  • 图片资产策略（生成图 / Picsum 占位）、logo 墙；
  • 落地页文案密度与「每屏一个卖点」。

本项目是常驻工具界面，不做首屏叙事。

5检查清单（改完界面逐条过）#

取值与一致性

  • 颜色/字号/圆角/阴影全部取自 token，无字面值
  • 强调色只有一个
  • 圆角只用四档且用法一致（小徽标用 --r-hair）
  • 按钮对比度达标，一屏一个 primary
  • 数字/包名用 mono，单位已中文化

结构与状态

  • 同类条目用列表行，不是一长串卡片
  • 加载 / 空 / 错误三态齐备
  • 空态也要有信息量：不要出现「一排全 0」而无说明的界面
  • 无重复渲染（同一信息不在同屏出现两次）
  • 无 em-dash

交互与可达性

  • 可点元素有 cursor: pointer 与悬停反馈
  • 键盘焦点可见（:focus-visible），抑制 outline 处已补替代
  • 动效在 prefers-reduced-motion 下关闭
  • 状态不只靠颜色表达
  • 弹层能自然关闭（失焦收起 / Esc）

主题与验证

  • 深浅两套主题都过一遍
  • 跑 python3 -m unittest tests.test_design_spec tests.test_dashboard_design_tokens
  • 若新增组件或变体，已回写本文件对应章节

附：双轨强制机制#

规范要真正拦住后续功能脱离，靠的是文档 + 测试双轨，而不是自觉。

层载体有效力
规则~/.dsh/AGENTS.md 的三条强制规则（语言 / UI 技能 / UI 规范双轨） 每次会话强制加载
规范docs/DESIGN.md（本文档的来源）需主动读
门禁 tests/test_design_spec.py + tests/test_dashboard_design_tokens.py（28 项） CI 强制
双轨

任何 UI 改动必须同时更新规范文档与补一条能真正失败的断言，缺一视为未完成。

反向验证

加完断言后必须故意制造一次违规，确认测试确实报错，再恢复。 只看到测试通过不算验证通过；永远通过的测试等于没有测试。

粒度

只守住有独立语义的顶层组件与不变量。不要为每个内部类名建门禁： 单页内部 CSS 类可达数百个，全覆盖只会产生海量误报，最终被绕过。
